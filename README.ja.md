## EverOtome とは

EverOtome は、**乙女ゲーム／ビジュアルノベル風の画面で AI コンパニオンとチャットできる、オープンソースのチャットフロントエンド**です。

ゲームそのものでも、ホスティングサービスでもありません。EverOtome は、あくまで「ガワ」のフロントエンドです。立ち絵、部屋の背景、CG、画面テーマをお好きなものに差し替えて、ご自身の AI バックエンドをつなぐと、**あなたのコンパニオンが乙女ゲームの画面へ引っ越してきます**。文字が中心だった AI との会話は、**立ち絵・シーン・CG・ボイス**をともなって、リアルタイムに物語が動いていく体験になります。

EverOtome 本体は vanilla JS 製の純粋なフロントエンド層で、AI モデル・バックエンドサービス・素材生成は含まれません。それらはご自身でご用意ください。つなぐ前に眺めるだけでも大丈夫です。サンプルキャラクターとデモアルバムが同梱されているので、clone すればコマンド一つでプレビューできます。

## ひと目でわかる

> 以下はすべて、バックエンドを接続したあとの姿です。接続前でも、サンプルキャラクター・デモアルバム・自動ツアーはそのままご覧いただけます。

**あなたができること**

- コンパニオンを乙女ゲームの部屋に住まわせて、そこでおしゃべりする。
- 立ち絵と表情差分を用意して、微笑んだり、眉をひそめたり、じっと見つめ返したりする姿を眺める（ガイド付き）。まばたきと口パクのテンポは設定のスライダーで調整できます。
- ボイスと通話：コンパニオンにすでに声があるなら、つなぐだけで画面の中から話してくれて、電話もかけてくれます。
- 部屋のテーマ、衣装、家具は自由に交換：素材フォルダに入れて、設定ファイルに書くだけです。
- 内蔵の CG アルバム：アップロード、並べ替え、シーンメモの記入ができて、好きな CG を選べばそのシーンから会話が始まります。

**コンパニオンができること**（バックエンド接続後）

- 気分にあわせて表情が変わる：会話の途中で、ふっと微笑んだり、視線を向けてくれたり。
- 自分の声のリズムにあわせて口が動く。
- 部屋の演出：部屋の今の様子を知っていて、気分しだいでテーマを替え、衣装を替え、家具を出したりしまったりします。
- シーンの演出：物語の進みにあわせてアルバムから CG を呼び出し、シーンが物語についてきます。

**さらに**

- PWA 対応。PC やスマホのホーム画面に追加できます。
- 内蔵テーマ 5 種：Crystal Swan、Rose Vow、Crimson Nocturne、Verdant Dawnsong、Snow Palace。
- EverOtome 自身のサーバーもテレメトリーもありません。素材と会話は、あなたが選んだバックエンドにだけ流れます。
- コードは MIT ライセンス。自由に改造してください（サンプル素材には別途の利用条件があります）。作ったものを見せていただけたら、とても嬉しいです。

## 機能ハイライト

### 💫 立ち絵が生きて動く

https://github.com/user-attachments/assets/d372d1d6-b900-4694-b619-47bd6e254b66

立ち絵はあなたが用意して、ガワが命を吹き込みます。まばたきして、呼吸して、口を開けて話します。

フルアニメーションには 9 枚の差分（A〜I：目の状態 3 種 × 口の状態 3 種）を使います。[フレーム仕様と生成ガイド](docs/sprite-guide.md)は手描きにも AI 生成イラストにも対応。待機中はまばたきと呼吸、返事のタイプライター表示中は**乙女ゲーム風の口パク**が一定のテンポで動きます。まばたきと口パクのテンポは、どちらも設定のスライダーです。

ボイス再生中は、口の動きが音声に切り替わります。音が鳴れば開き、間では閉じ、声が大きいところでは大きく開く。インターフェースは再生の前に音声ファイルを一度読み切ってリズムを計算しておくので、音声の再生処理には干渉しません。解析できない音声は定速の口パクにフォールバックします。ボイスをオンにしているとき、文がまだタイプ中で声が届いていない間は口を閉じて待ち、声が来てから開きます。

画像が 1 枚だけでも大丈夫。静止立ち絵モードもきれいに見えます。

### 🎭 表情と頬染め

https://github.com/user-attachments/assets/f9c0d84b-dbbc-4810-b563-1ee328446652

9 枚のフレームの上に、さらに 2 つのレイヤーを重ねられます。頬からふわっと浮かぶ赤らみと、目や口（または両方）を差し替える表情差分です。その下でキャラクターはいつも通りまばたきし、話し続けます。

この 2 層は、あなたの AI が自分から使います。返事に `[blush]` が入っていれば頬が染まり、`[expr:smile]` が入っていればその表情になります。マーカーは画面に届く前にインターフェースが取り除きます。どちらのレイヤーも外見ごとに `manifest.json` で宣言し、宣言のないキャラクターはそのままの姿を保ちます。バックエンド側の仕事は、返事にマーカーを書くことだけです。

`tools/gen_expression.py` は、その表情のために描いた全身イラストから差分パーツを切り出します。形式とワークフローは[立ち絵ガイド](docs/sprite-guide.md)へ。

**Character Lab**（`engine/demo/expression-lab.html`）は試着室です。選んだ外見を動いている立ち絵にそのまま反映して、その外見が宣言する表情ごとのボタンに、おしゃべりと頬染めのボタンも並べます。配線の前に、継ぎ目とテンポを確かめられます。選んだものは、次を選ぶまで点いたままです。同梱のサンプルキャラクターには微笑みの表情と頬染めレイヤーが付いているので、Lab には最初から見るものがあります。

### 🎨 テーマは 5 種、自作も

https://github.com/user-attachments/assets/21095216-909c-4861-a137-e3bc343c2700

Crystal Swan、Rose Vow、Crimson Nocturne、Verdant Dawnsong、Snow Palace。ワンクリックで切り替わり、部屋の背景、メッセージウィンドウ、吹き出し、ボタンまで一式そろって変わります。自作テーマは CSS 変数ひとそろいと素材 3 点で、設定ファイルに 1 エントリ足すだけ。もっと深く作り替えたいなら、CSS のソースはすべて手元にあります。直接編集してください。

### 🛋️ 部屋を AI にゆだねる（Room agency）

https://github.com/user-attachments/assets/734f6074-21df-43cc-9d38-1208e3e2fb0e

部屋を整えるのは、あなただけではありません。あなたの AI はテーマを替え、キャラクターの衣装を替え、家具を出したりしまったりできます。欲しい状態を自分の返事の中にマーカーとして書き、あなたのバックエンドがそれを読んで新しい状態を保存し、1 通の `room_state` メッセージとして押し戻します。インターフェースは届いた先で適用するので、2 台目のデバイスも同じ部屋にそろいます。

家具は設定ファイルに書くリストです。画像はどれか、どこに立つか、最初から出しておくか。デスクトップレイアウトに描画されます。サンプル設定には蓄音機がひとつ入っているので、家具タブは最初から試せます。ここまでは全部、バックエンドなしで外見パネルから手動操作できます。部屋を AI に任せるところだけバックエンドが必要で、メッセージの形は[バックエンド連携仕様](docs/backend-contract.md)にあります。

### 📖 ふたりの CG をアップロードして管理

https://github.com/user-attachments/assets/e3703b04-7575-4921-8c50-52f0f8b0f14f

CG はただの思い出ではなく、新しい物語の始まりにもなります。

AI と共有している CG をアップロードして管理できます。アルバムはデスクトップ用とモバイル用の素材を別グループで持ち、それぞれの画面に合う構図で表示します。内蔵マネージャーでアップロード、並べ替え、シーン情報の編集、各グループのオープニングシーンの指定まで。好きな CG からシーンを開けば、物語は毎回同じ部屋から始まらなくてもいいのです。

### 🌙 シーンを AI にゆだねる（Scene agency）

https://github.com/user-attachments/assets/3ffa2d4c-0748-4eaf-8f4a-a5ba31f5aadf

シーンを選ぶのは AI です。返事の中で映したいカードに印を付け、あなたのバックエンドがそれを 1 本の `cg_state` コマンドに変えると、画面は CG へフェードインし、物語にあわせてシーンを切り替え、終われば部屋へ戻ります。会話は一度も途切れません。だから、**彼があなたとしたいことが、そのまま目の前のシーンになります**。

同じ CG が物語の別の場面でもう一度現れてもいいし、シーンは物語が続くかぎり替わり続けられます。マーカーが画面に出ることはありません。インターフェースがすべての行から取り除きます。[バックエンド連携仕様](docs/backend-contract.md)に、マーカーの種類とそれを運ぶメッセージの一覧があります。

### 📞 ボイスと通話

既存の AI ボイスや通話フローを、乙女ゲーム式の画面につなげます。発信と通話タイマーはこちらで扱い、**彼の話すセリフは一文ずつ、字幕と Chat Log に流れます**。通話のあとは音声をリプレイでき、立ち絵の口はライブのときと同じように声についてきます。

### 💭 メッセージウィンドウと Thinking ボタン

ビジュアルノベル式のメッセージウィンドウ：ネームプレート、タイプライター表示、そして **Thinking ボタン**。ワンタップで、口に出さなかった心の声が見えて、もう一度タップすると戻ります。中身はあなたのバックエンドが提供します（返事に `thoughts` フィールドが付いていればボタンが現れ、なければ画面は静かなままです）。会話の全履歴は独立した Chat Log パネルにあります（スマホでは専用の THINKING タブ、デスクトップでは思考がログにインラインで並びます）。立ち絵だけを眺めたいときは、デスクトップでは目のボタンが表示オプション（メッセージウィンドウを隠す、立ち絵を隠す）を開き、スマホでは目のボタンひとつで Chat Log が畳まれます。

### 📱 デスクトップとモバイル

![デスクトップの 2 カラムレイアウトとモバイルの半身構図](docs/media/readme-devices-en.webp)

同じキャラクター体験が、デバイスをまたいで続きます。デスクトップは大きな立ち絵の 2 カラムレイアウト、モバイルは半身構図と折りたたみ式 Chat Log に自動で切り替わります。PWA でもあるので、対応ブラウザならスタンドアロンアプリとしてインストールできます。

### 🔌 つなぎたいものだけ、つなぐ

バックエンドが対応しているものだけ配線してください。チャット本体のほかに、**TTS（読み上げ）、通話、CG シーン制御、写真送信、モデル切り替え、サンドボックスチャット、メッセージのお気に入り、TTS 使用量メーター**の接続口が組み込まれています。画面はどちらでも散らかりません。CG、モデル切り替え、サンドボックス、お気に入りは設定しない限り描画されず、中途半端なボタンが残ることもありません（TTS・通話・写真送信の 3 つは常時オンで、内蔵の既定パスを使います。再生ボタンが不要なら `ttsEndpoint` を空文字にしてください）。小さく始めて、バックエンドの成長にあわせて増やしていけます。

## クイックスタート

### いちばん早い方法：AI アシスタントに渡す

この repo を AI アシスタントに渡して、こう伝えてください：

> 「EverOtome を動かして：`<repo の URL>`。まずゼロバックエンドのプレビューをして、そのあと `docs/` のドキュメントに沿って私の AI をつないで。」

### 自分の手で

プロジェクトを clone したら、コマンド一つでゼロバックエンドのプレビューが立ち上がります。

`serve.py` はプレビュー用の静的ファイルサーバーで、バックエンドの中継はしないため、このサーバー経由ではチャットはつながりません。

```bash
cd engine
python serve.py       # http://127.0.0.1:8300
# python コマンドが無い場合は：python3 serve.py
```

（EverOtome 本体はフレームワーク依存ゼロです。）

何も設定しなくても動きます。サンプルキャラクター **Rye**（微笑み表情と頬染めレイヤー付き）、デモ CG アルバム、家具ひとつが同梱で、コアの操作（まばたき、テーマ切り替え、外見パネル、Character Lab）はそのまま動きます。大きめの機能が動く様子を見るなら `demo/tour.html?seg=cg` へ。デモデータで動く、ゼロバックエンドの自動ツアーです。自分の AI をつなぐには：

```bash
cp config.example.json config.json       # macOS / Linux
copy config.example.json config.json     # Windows
# config.json を編集して、バックエンドと素材の場所を指定します
```

ライブチャットは `/ws` のような同一オリジンのパス上の WebSocket で動くため、バックエンドは `engine/` フォルダを自分で配信するか、同じリバースプロキシの後ろに置いてください。この repo で動作確認した Caddy／nginx の例は[バックエンド連携仕様](docs/backend-contract.md#deployment-one-origin)にあります。

バックエンドが必要な機能（メッセージ送受信、通話、CG プッシュ）は、実装したサービスをつなぐまで動きません。**これは想定どおりの動作で、壊れているわけではありません。**バックエンドが動いていない間、ブラウザのコンソールには `config.json` とサンプルのバックエンドパス（`/api/history`、`/api/v4/chat-clear`）の 404、そして WebSocket 再接続エラーが繰り返し出て、メッセージウィンドウには未接続の表示が出ます。サンプルキャラクター、テーマ、アルバム、ツアーはそのまま動きます。

## 言語

現時点のインターフェース言語は繁体字中国語と英語の 2 つで、既定では訪問者のブラウザ言語に従います（日本語 UI はまだ同梱されていませんが、下記の手順で追加できます）。**設定 → 言語**からいつでも切り替えられ（その端末で記憶されます）、`config.json` に `"locale": "zh-Hant"` や `"en"` を書けば全員の言語を固定でき、URL に `?lang=en` を付ければその読み込みだけ強制できます。`config.json` に書く名前（テーマ・衣装・家具）と、バックエンドが返す CG カードの `name`／`desc` は、単一の文字列でも、言語ごとの指定でも構いません：`"label": { "zh-Hant": "水晶天鵝", "en": "Crystal Swan" }`。

言語を追加するには、`engine/js/locales/en.js` を `engine/js/locales/<code>.js` にコピーして値を翻訳し、`engine/js/i18n.js` の先頭でその辞書を import して `DICTS` に加え、`SUPPORTED_LOCALES` と `LOCALE_NAMES` にコードを登録します。テストスイートが、全言語でキーがそろっていることと、サンプルアルバムの各カードに各言語の名前があることをチェックします。

## プロジェクトの状態

EverOtome は現在 **Beta** です。コア機能は安定して使えますが、設定ファイルの形式とバックエンドプロトコルは 1.0 までに変わる可能性があります。

## 動作要件

- モダンブラウザ（Chrome、Edge、Safari、Firefox の近年のバージョン）
- Python 3（3.7 以上）：ローカルプレビュー（`serve.py`）、接続チェッカー（`tools/check_integration.py`）、HTTP ブリッジ（`examples/http-bridge/`）の起動に使います。追加パッケージは不要です
- `tools/` の素材ツール（表情パッチ、位置合わせチェック、セーフゾーンテンプレート）：Python 3 と Pillow（`pip install pillow`）
- ライブチャット・通話・CG プッシュには、[バックエンド連携仕様](docs/backend-contract.md)を実装したバックエンドが必要です

---

## プライバシーとデータの流れ

- EverOtome にテレメトリーや解析コードは含まれず、メンテナがあなたのデータを受け取るサーバーも運用していません。純粋な静的フロントエンドです。
- 「アップデートを確認」が唯一の外向き接続で、ホーム画面または設定ページのボタンを押したときにだけ動きます。GitHub から公開のバージョン情報を取得するだけで、何もアップロードせず、バックグラウンドで勝手に確認することもありません。
- 会話内容はブラウザストレージに書き込みません。メッセージはライブで描画され、履歴はあなたのバックエンドが持ちます。ブラウザに保存されるのは、インターフェースの設定と表示状態だけです。
- あなたのメッセージ・写真・音声は、設定ファイルで指定したバックエンドにだけ送られます。
